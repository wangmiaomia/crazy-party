V86.1 音乐问题根因与修改结果

根因 1：V86 的 realBgm 监听 pause / waiting / stalled / suspend，并且还有每 1.6 秒一次的 watchdog。
手机端遇到正常缓冲或系统临时挂起时，watchdog 会主动再次 play，某些情况下还会重新进入兼容播放路径，导致浏览器顶部加载进度反复出现，听感像歌曲一卡一卡、重新加载。

根因 2：V86 在 HTMLAudio 播放判断失败时会创建第二条 Web Audio BufferSource 兼容链路；原 HTMLAudio 可能随后恢复，因此存在两路音频重叠的可能。

根因 3：V86 的暂停按钮对真实歌曲主要是 volume=0，并没有真正 pause；同时 watchdog 把 pause 事件当成需要恢复的异常，所以用户主动暂停可能被自动拉起。

根因 4：06 唱片主题同时存在 realBgm 与 VinylBGM 两套播放器。虽然启动页做了特殊处理，但交互 SFX 的 action() 在未 started 状态下仍可能触发 PartyAudio.startTheme，造成第二条背景音乐链路。

V86.1 修改：
- 删除所有 1.6 秒 watchdog。
- 不再把 suspend / waiting / stalled 当成需要重新加载歌曲的信号。
- 删除 Web Audio 背景音乐 fallback，只保留一个 HTMLAudioElement 播放真实歌曲。
- 用户点击暂停时直接 realBgm.pause()；恢复时从原 currentTime 继续，不归零。
- 页面从后台返回时，只在“用户没有主动暂停”的前提下恢复播放。
- 06 唱片主题只由 VinylBGM 播放背景歌曲，PartyAudio 仅保留短交互音效；仍然必须落针后才播放。
- 双端预览只由父级一个播放器负责真实歌曲，两个 iframe 不再各自启动背景音乐。
- 5 首 MP3 从 256/320 kbps 优化为 160 kbps，单文件约 3.7–5.2 MB，降低手机网络缓冲压力。
- 所有 01–08 CSS 与 V86 原版逐字一致，没有加入 V87 手机分页布局。
